## Implementation and boundaries

- Existing `HardwareTelemetryProvider` owns one LHM `Computer` for CPU/GPU/Storage/Network and captures one startup hardware snapshot. `storage.N` and `network.N` sort LHM identifiers ordinally within each kind; duplicate identifiers fail startup. Storage identifiers combine class and drive number; Network uses interface ID. Provider identifiers never enter Core MetricIds or WidgetHost. The order is deterministic for one discovered startup set, not proven persistent across reboot or re-enumeration.
- Storage suffixes: `usage`, `read.bytes_per_second`, `write.bytes_per_second`, `total.bytes`, `free.bytes`. Network suffixes: `download.bytes_per_second`, `upload.bytes_per_second`, `usage`. LHM's general `Data` comment says 2^30 bytes, but StorageDevice uses BlackSharp's decimal GB converter. Cerith multiplies storage Data readings by 1,000,000,000; Throughput remains B/s and Load remains %. Invalid or missing never becomes measured zero. Free Space requires Used Space presence because LHM can turn absent `TotalFreeSize` into zero. Exact mapping and discarded candidates are in `docs/METRICS.md`.
- Removed startup devices become `Unavailable` on the next publish tick. New devices and re-added interfaces wait for a service restart before index assignment. LHM may retain a previous storage rate after IOCTL failure or a network sensor after a handled interface error; this slice cannot detect those internal failures. No generic hotplug system was added.
- WidgetHost shows a compact `storage.0` and `network.0` sample alongside CPU/RAM/GPU/VRAM/fan. No first snapshot within five seconds becomes `unavailable`, matching the zero-Storage machine. All startup-discovered device indices publish through the bus. The UI does not imply that `network.0` is active or that only one device exists.
- Deferred: Storage temperature (NVMe/SSD/HDD names differ and upstream can create zero from absent data), Total Activity (I/O activity, not capacity usage), SMART/life/lifetime counters, accumulated network totals, addresses and M1 diagnostics. No new package, Core→LHM dependency, provider framework or extra `Computer`.
