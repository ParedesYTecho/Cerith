## Purpose

Evidence classes: **D** = official documented behavior; **O** = official client/backend behavior observed in first-party source or a sanitized local probe, without a supported public backend API promise; **R** = independently implemented reference. R is corroboration, never authority. Windows availability of the provider/source does not imply a reference monitor itself runs on Windows.

## Codex — evidence and source selection

Primary sources:

- **C1 (D):** [Official app-server documentation](https://learn.chatgpt.com/docs/app-server), specifically account/rateLimits/read, account/read and authentication modes. Public documentation exposes structured rate-limit reads. Retrieved Markdown via HTTPS after the web reader failed on the old developers URL and rejected text/markdown; no authenticated website scraping was needed.
- **C2 (D):** [Official authentication](https://learn.chatgpt.com/docs/auth), including file/keyring/auto/ephemeral credentials and managed refresh. [Official pricing](https://learn.chatgpt.com/docs/pricing) separates plan allowance, shared usage and paid credits; it is not a fixed token-denominator contract.
- **C3 (O):** official [openai/codex revision `2a34aef79484bf769b4b225f3f595755f2962170`](https://github.com/openai/codex/tree/2a34aef79484bf769b4b225f3f595755f2962170). [`rate_limit_resets.rs`](https://github.com/openai/codex/blob/2a34aef79484bf769b4b225f3f595755f2962170/codex-rs/backend-client/src/client/rate_limit_resets.rs) performs GET on /wham/usage (or /api/codex/usage for another backend path style). [`client.rs`](https://github.com/openai/codex/blob/2a34aef79484bf769b4b225f3f595755f2962170/codex-rs/backend-client/src/client.rs) maps used percentages, duration seconds and reset seconds to app-server data and passes the selected ChatGPT account header. [`account_processor.rs`](https://github.com/openai/codex/blob/2a34aef79484bf769b4b225f3f595755f2962170/codex-rs/app-server/src/request_processors/account_processor.rs) calls auth_with_http_client_factory; [`manager.rs`](https://github.com/openai/codex/blob/2a34aef79484bf769b4b225f3f595755f2962170/codex-rs/login/src/auth/manager.rs) can proactively refresh managed credentials. A read request is therefore not proof of zero auth mutation.
- **C4 (O):** raw first-party [`RateLimitWindowSnapshot`](https://github.com/openai/codex/blob/2a34aef79484bf769b4b225f3f595755f2962170/codex-rs/codex-backend-openapi-models/src/models/rate_limit_window_snapshot.rs), [`RateLimitStatusDetails`](https://github.com/openai/codex/blob/2a34aef79484bf769b4b225f3f595755f2962170/codex-rs/codex-backend-openapi-models/src/models/rate_limit_status_details.rs) and [`RateLimitStatusPayload`](https://github.com/openai/codex/blob/2a34aef79484bf769b4b225f3f595755f2962170/codex-rs/codex-backend-openapi-models/src/models/rate_limit_status_payload.rs). Public [`GetAccountRateLimitsResponse`](https://github.com/openai/codex/blob/2a34aef79484bf769b4b225f3f595755f2962170/codex-rs/app-server-protocol/schema/typescript/v2/GetAccountRateLimitsResponse.ts), [`RateLimitWindow`](https://github.com/openai/codex/blob/2a34aef79484bf769b4b225f3f595755f2962170/codex-rs/app-server-protocol/schema/typescript/v2/RateLimitWindow.ts) and [`CreditsSnapshot`](https://github.com/openai/codex/blob/2a34aef79484bf769b4b225f3f595755f2962170/codex-rs/app-server-protocol/schema/typescript/v2/CreditsSnapshot.ts) expose distinct bucket/window/credits concepts. These are protocol evidence, not guarantees that every optional field exists for every plan.
- **C5 (local O):** one bounded GET to https://chatgpt.com/backend-api/wham/usage on this Windows host returned HTTP 200 using existing file-auth access token and selected-account header in memory. Observed primary duration 18000 seconds and secondary 604800; used_percent, reset_at, reset_after_seconds, account_id, plan_type, allowed, credit flags/balance presence and an additional bucket were present. Installed CLI reported 0.159.0, but it was not launched for authenticated reads. No credential write, refresh, cookie extraction, auth copy, saved payload or personal identifier was needed. Actual account values are not recorded here. This probe verifies access/shape on one account, not universal windows, identity correctness, plan coverage or cross-validation.

## Claude — documented observation versus external endpoint

Primary sources: **A1 (D)** [official Claude Code statusline JSON](https://code.claude.com/docs/en/statusline), requiring v2.1.251 or later for the described rate-limit recipe, documents `rate_limits.five_hour.used_percentage` / `resets_at` and `seven_day` equivalents; fields may be independently absent and are removed after reset. Gateway spend_limit is a separate ratio that can exceed 100, not a bounded remaining allowance. **A2 (D)** [authentication](https://code.claude.com/docs/en/authentication) and [environment variables](https://code.claude.com/docs/en/env-vars) describe official credential handling and configuration. **A3 (D)** [Max plan usage](https://support.claude.com/en/articles/11049741-what-is-the-max-plan), [usage credits](https://support.claude.com/en/articles/12429409-manage-usage-credits-for-paid-claude-plans) and [limit resets](https://support.claude.com/en/articles/17007452-what-is-a-limit-reset) establish separate included allowances, extra usage and reset actions. **A4:** [official public Claude Code revision `684800b206824dfd0cc8a876e8604b20f72c3617`](https://github.com/anthropics/claude-code/tree/684800b206824dfd0cc8a876e8604b20f72c3617) did not expose an auditable client implementation of /api/oauth/usage during the bounded investigation; it does not upgrade the external endpoint schema to an official API contract.

## Antigravity — groups and windows, not guessed model quotas

Primary sources: **G1 (D)** official [usage/quota command](https://antigravity.google/docs/cli/commands/usage/) and [CLI installation](https://antigravity.google/docs/cli/install/) establish interactive /usage (/quota) and Windows availability. The pinned official [CLI changelog `77b1aad0cb850c184a987661b149985de41a3568`](https://github.com/google-antigravity/antigravity-cli/blob/77b1aad0cb850c184a987661b149985de41a3568/CHANGELOG.md), section **1.1.11**, explicitly supports `agy -p /usage --output-format json` as a structured read-only slash-command response without starting an agent turn, consuming quota or leaving a conversation. A collaborator confirms the exact command in [issue #590](https://github.com/google-antigravity/antigravity-cli/issues/590). Generic [headless mode](https://antigravity.google/docs/cli/headless/) JSON inference examples alone would not establish that; the changelog supplies the missing primary evidence. **G2 (D)** [plans](https://antigravity.google/docs/plans) and [models](https://antigravity.google/docs/models) describe baseline allowances, overage credits and shared model groups. **G3 (R, user reports hosted in the official issue tracker)** CLI issues [#825](https://github.com/google-antigravity/antigravity-cli/issues/825) and [#962](https://github.com/google-antigravity/antigravity-cli/issues/962) quote quota-field/admission observations. Hosting does not make them first-party confirmation; they are scoped reports, not confirmed universal root causes or supported wire contracts. Modern internal summary/local RPC evidence is corroborated by the pinned R sources below.

Pinned R evidence and unresolved disagreements:

- [CodexBar research](https://github.com/steipete/CodexBar/blob/25bba9b7fd9ce83c33053958f7366e23b2dc8a82/docs/antigravity.md): prefers modern RetrieveUserQuotaSummary; local GetUserStatus/model-config and cloud OAuth fallbacks are narrower/older. Uniform full-looking model fractions are treated cautiously.
- [OpenUsage research](https://github.com/robinebers/openusage/blob/2d2eabe5e2764db9eff5ecf4dc7952443787659f/docs/providers/antigravity.md): shared pool model and local/cloud paths; account isolation matters. Its “rolling” wording is external interpretation, not proof of Google's algorithm.
- [Gengchou poller](https://github.com/ynjmxn/gengchou/blob/4d02b9d1f85e806c92c4defc8e8c4c822467b6f3/src/poller.rs): Windows credential reuse/cloud quota summary, Code Assist project discovery, restricted legacy retrieveUserQuota/model fallbacks. No local GetUserStatus route in that adapter.
- [AI Limits adapter](https://github.com/napxlexn/ailimits/blob/a42bbd043070538ff5c4161b7eda952720173345/src/providers/antigravity.rs): requires project identity and prioritizes retrieveUserQuotaSummary; rejects older retrieveUserQuota as trustworthy consumption, unlike Gengchou's restricted acceptance. This disagreement is **not resolved by a local probe**; legacy source is degraded until proven for a specific schema/group.
- [TokenTracker limits](https://github.com/xiufengsun/TokenTracker/blob/daa6c55099d34458ff773f6c1edd777f16fb7693/src/lib/usage-limits.js): cloud summary plus local summary→GetUserStatus→model configuration; remote path need not resolve project first. Its legacy min/max window mapping and separate transcript accounting are heuristics/activity, not authoritative quota normalization.

Resolution for ordering: modern shared-group/window summary outranks legacy per-model availability. Do not accept fetchAvailableModels.quotaInfo (on internal cloudcode/daily-cloudcode hosts) as complete quota just because it returns 1.0; distinguish “model available” from allowance remaining. Preserve missing fraction even where an external client treats missing-with-reset as exhausted. Code Assist project necessity, stable group IDs, exact JSON schema, scope/identity and internal error/reset mechanics remain explicit later-provider research/validation gates.

The documented CLI >=1.1.11 print-mode quota output is the **preferred source candidate for Antigravity**, not a proven zero-auth-mutation runtime guarantee. Before adopting it, verify installed version and documented slash dispatch, validate the actual quota schema, bounded output/deadline, active account binding and whether startup/invocation renews credentials. Installation docs also describe automatic browser login if no saved session exists. Do not run it against the user's auth to discover side effects. If these gates fail, investigate an already-running loopback summary with verified process ownership and ephemeral CSRF; only then consider minimal cloud credential reuse. None of these fallbacks is implemented or silently selected now. An unavailable automation source is recorded as a limitation, not replaced by inferred activity.
